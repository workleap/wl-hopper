Hopper publishes an [agent Skill](https://www.npmjs.com/package/skills): a folder of documentation
your coding agent loads on demand. It is the lowest-friction way to teach an agent Hopper — one
command, no MCP client, no per-project configuration, and it keeps working offline afterwards.

## Install

```bash
npx skills add https://hopper.workleap.design
```

That is the whole setup. The CLI discovers the skill, downloads it, and wires it into whichever
agents it finds — Claude Code, Cursor, Codex, Cline, and others.

## What you get

About 3 MB across ~230 files, installed into `.agents/skills/hopper` (and symlinked into your
agent's own skills directory):

- `SKILL.md` — the rules, the workflow, and an index of everything else.
- `references/components/` — one file per component, plus the catalog.
- `references/api/` — props, types and defaults as JSON.
- `references/guides/` — installation, theming, layout, forms, styling, escape hatches.
- `references/tokens/` — token guidance and the token-to-prop-value maps for both themes in light and dark.
- `references/icons/` — every icon, searchable.
- `references/workflows/` — building a screen, and turning a Figma frame into Hopper JSX.
- `scripts/validate-hopper-code.mjs` — a runnable linter for Hopper JSX.

Agents only read the files they need, so the skill costs very little context until it is used.

The [MCP server](/getting-started/ai-for-agents/mcp-server) and
[llms.txt](/getting-started/ai-for-agents/llms) each have their own page.

**Use both the skill and the MCP server.** The skill gives every agent a solid baseline with no
setup; the MCP server adds always-current data and fuzzy icon search on top. When both are present,
the skill tells the agent to prefer the MCP server.

## Keeping it up to date

The skill is a snapshot taken when you installed it, and it is regenerated on every documentation
deploy. Re-run the install command to pick up newer components and tokens:

```bash
npx skills add https://hopper.workleap.design
```

`SKILL.md` records the `@hopper-ui/components` version it was built from, under `metadata.version`.

## Validating your code

The skill ships the same linter the MCP server runs:

```bash
node .agents/skills/hopper/scripts/validate-hopper-code.mjs src/MyComponent.tsx
```

It checks design token usage, prop values, `UNSAFE_*` props, component structure and layout
patterns, and exits non-zero when it finds errors. For TypeScript files it uses `typescript` or
`@typescript-eslint/parser` from your project; for plain JSX it falls back to a bundled parser and
needs nothing at all.

## Contributing

The skill is generated from this documentation site by
`apps/docs/scripts/buildSkills.ts`, driven by `apps/docs/ai-pipeline/skills.config.ts`. To work on
it locally:

```bash
pnpm doc:generate
pnpm build:doc                    # contentlayer output the AI docs build needs
pnpm build:ai-docs                # slow; only when content changed
pnpm --filter=docs build:skills   # fast; re-run freely
pnpm doc:start
```

Then install it from your dev server, from a scratch directory outside the repo:

```bash
npx skills add http://localhost:3000
```

See `apps/docs/ai-pipeline/CONTRIBUTING.md` for how to add or change what the skill contains, and
[ADR 0002](https://github.com/workleap/wl-hopper/blob/main/docs/adr/0002-hopper-agent-skill.md) for
why it is built this way.
